# Tentacle HRV — 多模态 AI 闭环体感控制系统

基于 DeepSeek 多模态 API，整合 **平板摄像头拍照 + 心率手环 BLE 数据 + 网页控制面板 + ESP32 蓝牙中转 + 蓝牙玩具反馈** 的实时闭环控制系统。

> **本项目采用 DLC 模块化架构**，核心系统负责基础闭环，九个 DLC 分别扩展不同能力，可独立启用或禁用。

## 📦 DLC 模块总览

| DLC | 名称 | 功能 | 依赖 |
|-----|------|------|------|
| 核心 | 基础闭环 | 摄像头 + 心率 + AI 决策 + 指令下发 | 必选 |
| DLC1 | AI 语音朗读 | TTS 语音合成，AI 回复自动朗读 | edge-tts |
| DLC3 | 随机事件系统 | 弹窗事件 + 玩家选项 + 心率联动策略 | events.json |
| DLC4 | 手动控制模式 | 网页端滑块调节强度/时长/波形，手动发送指令 | 无 |
| DLC5 | 自定义角色接口 | 网页端粘贴 SYSTEM_PROMPT，自由创造角色 | 无 |
| DLC6 | 对话记忆增强 | AI 记住近期互动历史，角色更连贯 | 无 |
| DLC7 | 数据可视化面板 | 心率曲线 + 指令强度柱状图 | Chart.js |
| DLC8 | 声音氛围系统 | 根据心率自动生成背景音效 | Web Audio API |
| DLC9 | Web 配置后台 | 网页端修改安全阈值、重载事件池 | 无 |

> **注**：DLC2 未使用，编号从 DLC1 跳到 DLC3 是有意设计。

## ✨ 核心功能特性

- 📷 平板摄像头每 3 秒拍照上传，AI 实时分析画面
- ❤️ 通过 ESP32 读取心率手环数据（HR/IBI），后端计算 **HRV（RMSSD）** 并维护本会话静息基线
- 🧠 DeepSeek 多模态模型决策，输出 `SET 强度 时长 波形` 或 `STOP` 指令
- 🛡️ **双重**安全策略：绝对心率（>130 强制 STOP，110~130 限幅 50%）+ 相对静息基线的偏离（HRV 降幅 / 心率升幅），图片超时暂停 AI

## ❤️ HRV 引擎（本项目的核心差异点）

原版方案只让 AI「看画面猜状态」；本项目把**生理状态**接进闭环，让 AI 读到「相对自己静息基线的偏离」。

### 指标与基线

| 项目 | 默认值 | 说明 |
|---|---|---|
| 指标 | RMSSD | `sqrt(mean(diff(IBI)²))`，短时心率变异性最常用的指标 |
| 滑动窗口 | 120 秒 | 窗口内最多保留 512 个 IBI 样本，可在管理后台改 |
| 静息基线来源 | 自适应采集 | 优先级：**手动填写**（`RESTING_HR`/`BASELINE_RMSSD`）> 本会话开局自适应采集（约 60~90 秒内、累计 ≥12 个有效 IBI）> 不可用 |
| 数据判活 | 10 秒 | 心率数据超过 10 秒未更新即视为「不可用」，避免拿陈旧值做限幅判断 |
| 会话重建 | 600 秒 | 静息超过 10 分钟无数据后，重新采集基线 |

基线只允许朝「更放松」方向缓慢自适应：这是为了避免长时间紧张把基线一路拖低、最终让保护阈值失效（HRV 类安全策略最常见的失效模式）。

### 状态判定与硬约束

AI 每轮拿到的「生理状态块」由后端实测注入（禁止 AI 自行编造生理数值），判定维度是**心率相对基线的升幅**与**HRV 相对基线的降幅**：

| 判定 | 条件 | AI 收到的战术指引 |
|---|---|---|
| 过载 | 心率超基线 ≥50 bpm 或 HRV 降 ≥40% | 只能 STOP |
| 紧张／开始疲劳 | 心率超基线 ≥30 bpm 或 HRV 降 ≥20% | 只做轻度试探 |
| 兴奋且耐受良好 | HRV 高于基线 ≥25% 且心率升幅 ≤15 bpm | 可适度提高强度 |
| 状态平稳 | 其余情况 | 按剧情节奏推进 |

以上 AI 侧的纪律之外，**后端还有一层不依赖 AI 自觉的硬约束**（`clamp_command`）：

- **熔断**（直接改判 STOP）：心率 >130；或心率超基线 ≥65 bpm（且已进入限幅区）；或 HRV 较基线下降 ≥60%
- **限幅**（压到 `HR_LIMIT_MAX`，默认 50，且单次时长砍半）：心率 ≥110；或心率超基线 ≥45 bpm；或 HRV 降幅 ≥40%
- 强度统一不超过 `PC_LEVEL_CAP`（默认 80）；时长不超过 `MAX_DURATION_S`（默认 300 秒）

> **两处已知语义落差（如实说明）**：① 后端上限 80 与设备物理上限 60 之间是**钳制**关系——设备 profile 的 `max_intensity` 为 60，所以 AI 要 70 和要 100 的实际强度相同（都是 60 档），不存在比例缩放；② 心跳/心率跃迁（受惊、设备重连造成数据段拼接）会触发 IBI 窗口**段重置**：旧窗口整体作废、静息基线保留，重新累积 RMSSD 需要约 2 拍；这是为了不让跨段的巨大差分把 RMSSD 假性抬高。

### 怎么用

- 什么都不用配：开机后约 60~90 秒自动建立基线，状态栏会显示 `HRV(RMSSD)` 与 `静息基线`
- 已知自己的静息心率：在「⚙️ 管理后台」填 `静息心率`（填数字即以你填的为准，填 `0` 用自适应）
- 换人/换场景：点后台的「重置 HRV 会话」，会重新采集基线
- 状态栏显示「未建立（等待采集）」= 手环未接入，或基线样本还不够，此时系统**不做 HRV 限幅**，只按绝对心率判断

## 🎮 DLC 详细说明

### DLC1 — AI 语音朗读
- 勾选后，AI 回复自动朗读（中文女声，可换音色）
- 依赖 `edge-tts`，需联网

### DLC3 — 随机事件系统
- AI 适时触发事件，弹窗展示，限时选择
- 玩家选择直接作为行动，影响后续剧情
- 心率 >130 仅允许放松事件；110~130 有 80% 概率替换为放松事件
- 事件池由 `events.json` 配置，可自行增删

### DLC4 — 手动控制模式
- 网页端滑块调节强度（0-100）、时长（1-60秒）、波形
- 一键发送 SET / STOP 指令

### DLC5 — 自定义角色接口
- 网页端粘贴自定义 SYSTEM_PROMPT，保存后 AI 换人设
- 留空保存即可恢复默认角色

### DLC6 — 对话记忆增强
- 后端维护最近 20 条交互记录
- 每次调用 AI 时注入最近 5 条历史，增强连贯性

### DLC7 — 数据可视化面板
- 实时心率折线图
- 指令强度柱状图
- 记录最近 200 个数据点

### DLC8 — 声音氛围系统
- 根据心率自动生成不同频率和音量的背景音效
- 心率正常低频柔和，偏高紧张，危险高频急促
- 勾选「氛围音效」开启，纯浏览器端实现

### DLC9 — Web 配置后台
- 网页端修改心率熔断阈值、限幅阈值、强度上限、最大时长
- **HRV 参数**：静息心率（0=自适应）、HRV 基线（RMSSD）、HRV 限幅/熔断降幅、心率超基线限幅/熔断、HRV 窗口长度
- 可「重置 HRV 会话」（重新采集静息基线）、重新加载事件池
- 运行时生效，重启后恢复默认（当前未持久化）

## 🚀 快速开始

### 1. 配置环境变量

复制 `.env.example` 为 `.env`（或手动创建），填写以下内容：

```ini
DEEPSEEK_API_KEY=你的DeepSeek密钥
# 官方正式名（旧别名 deepseek-v4-flash-vision-exp 已下线，继续用会静默路由或直接 400）
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_TIMEOUT=30
DEEPSEEK_MAX_TOKENS=1800
DEEPSEEK_THINKING=enabled
DEEPSEEK_THINKING_BUDGET=1024
SERIAL_PORT=COM3
SERIAL_BAUD=115200
INTERVAL_SECONDS=3
IMAGE_MAX_WIDTH=640
IMAGE_STALE_TIMEOUT=10
# 访问口令：留空则每次启动自动生成随机口令并打印一次；想固定就填一个强口令
ACCESS_KEY=
BASIC_USER=admin
BASIC_PASS=
```

每个变量的含义见 `.env.example` 的注释；`thinking` 三档（`enabled` 带推理预算 / `disabled` 最快最省 / `auto` 不传参）的取舍也写在那里。

### 2. 启动后端服务

```bash
cd tentacle-hrv
python server.py --port 8080
```

### 3. 启动内网穿透（可选，供平板外网访问）

```bash
# 用户名/主机/端口换成你自己的隧道服务；这些属于个人凭据，不要写进仓库
ssh -o ServerAliveInterval=30 -N -R 0:127.0.0.1:8080 用户名@隧道主机 -p 端口
```

> 也可用 `start_all.bat` 一键启动：它会从 `.env` 读取 `ACCESS_KEY` 与 `TUNNEL_SSH`（未配置 `TUNNEL_SSH` 时只在本机运行）。

### 4. 打开控制页面

- 本机：`http://127.0.0.1:8080/?key=<你的访问口令>`
- 平板：`https://你的域名/?key=<你的访问口令>`

## 🔌 ESP32 固件

固件位于 `esp32_firmware/esp32_firmware.ino`，使用 Arduino IDE 烧录。

> ⚠️ **重要**：固件 BLE 部分基于 arduino-esp32 core **3.x API**，请勿使用 1.x/2.x 核心编译（会报错）；本项目以 **esp32 core 3.3.11** 编译验证通过（Flash 83% / RAM 12%）。

命令行烧录示例（可选，需安装 [arduino-cli](https://arduino.github.io/arduino-cli/)）：

```bash
arduino-cli compile --fqbn esp32:esp32:esp32 esp32_firmware
arduino-cli upload -p COM3 --fqbn esp32:esp32:esp32 esp32_firmware
```

固件采用"设备类型 Profile"框架（见 `docs/体感设备适配说明.md`）：默认体感设备 A profile（UUID `0000FFE0`/`0000FFE1`、强度上限 60，行为与旧版一致），并预留体感设备 B类 profile（`TOY_PROFILE_MALE_MST`）待逆向。需更换玩具时，把逆向所得 UUID/协议填入 `esp32_firmware/toy_profiles.h/.cpp`，并在 `esp32_firmware.ino` 顶部切换 `ACTIVE_TOY_PROFILE`。心率手环连接参数见代码 HR_* 宏。

## ⚠️ 安全注意事项

- 不要将 `.env`、`certs/`、`models/`、`ffmpeg.exe`、`local.secrets.bat`、`*.local.md` 提交到 Git
- **口令不再是「默认 123456」**：`ACCESS_KEY` / `BASIC_PASS` 从 `.env` 读取；**留空则每次启动自动生成随机口令并在启动日志里打印一次**，所以服务经隧道暴露到公网时不会带着一个人人皆知的弱口令（仍建议在 `.env` 里固定成自己的强口令）
- 心率超过 130 自动强制 STOP，HRV 相对基线大幅下降也会强制 STOP（阈值均可在 DLC9 管理后台修改）
- 蓝牙玩具物理强度上限已在固件中限制为 60%
- DLC3 随机事件在心率偏高时自动降级为放松事件
- 网页在启动摄像头时会**同时申请麦克风**并周期性上传录音用于离线语音识别；页面没有独立的录音开关，请自行注意这一点

## 📚 常见问题

### 平板提示无法访问摄像头？

必须使用 HTTPS 访问。

### 语音识别不可用？

检查 vosk、pydub、ffmpeg 是否安装，模型是否放在正确路径。

### AI 语音朗读没有声音？

确保已安装 edge-tts 并联网，勾选「AI语音朗读」。

### 管理后台修改的阈值没生效？

运行时生效，重启后恢复默认（DLC9 当前未持久化）。

### 状态栏的 HRV 一直显示「未建立（等待采集）」？

三种可能：① 手环没有连上（ESP32 只认广播里带标准心率服务 `0x180D` 的手环）；② 刚启动、有效 IBI 样本还不到 12 个（约需 60~90 秒）；③ 手环没有上报 RR-Interval——**没有 IBI 就没有 HRV**，此时固件会上报 `IBI:0`，后端按「无 IBI」处理。可以先看后端日志里有没有持续打印 `[心率] HR=.. IBI=..`。

### 为什么填了静息心率，HRV 判定就变了？

填了 `RESTING_HR`（后台「静息心率」，非 0）即以你填的值为基线，不再自适应采集；填 0 恢复自适应。改动会同时重建 HRV 会话，避免旧样本与新基线混用。不知道自己静息心率时留 0 即可。

### 换了使用场景，基线不对了怎么办？

点管理后台的「重置 HRV 会话」，会清空 IBI 窗口与基线并重新采集（约 60~90 秒）。

### AI 偶尔不输出指令 / 输出无法解析？

提示词里已强制「正文最后一行必须是独立的 `SET …`/`STOP`」，解析器也只认正文最后 3 个非空行里的指令行。若仍出现，日志里会有 `AI 输出无法解析`，请把该轮完整输出贴到 Issue。
