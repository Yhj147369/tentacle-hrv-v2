**Tentacle HRV 项目更新（合订本，本楼持续更新）**

**一句话简介**
Tentacle HRV 是一个多模态 AI 闭环体感控制系统：平板摄像头画面 + 心率手环的 HR/IBI 数据交给 DeepSeek 多模态模型，模型输出 `SET 强度 时长 波形` 或 `STOP`，再由 ESP32 经 BLE 驱动反馈设备。核心是让 AI 读到使用者的生理状态。

**当前版本与更新要点**
最新 Release 为 v1.8.0（GPL-3.0）；`main` 分支另有尚未打 tag 的改动（HRV 引擎与会话静息基线、安全层修复），以仓库为准。v1.0.0～v1.8.0 要点合并如下：

- v1.0.0：核心闭环——定时拍照上传、心率读取、AI 决策、指令下发
- v1.1.0：DLC3 随机事件与剧情分支（事件池 `events.json`；心率偏高降级为放松事件）
- v1.2.0～v1.3.0：DLC1 AI 语音朗读（edge-tts）、DLC4 手动控制、DLC5 自定义角色接口
- v1.4.0～v1.7.0：DLC6 对话记忆、DLC7 数据可视化、DLC8 声音氛围、DLC9 Web 配置后台
- v1.8.0：ESP32 固件修复——波形字符串解析、时长自动停止、BLE 迁移到 arduino-esp32 core 3.x，已在 core 3.3.11 下真实编译通过；同时引入设备类型 Profile 框架：默认**体感设备 A**（0xFFE0/0xFFE1、上限 60，报文与旧版一致），并预留**体感设备 B** 骨架

**硬件需求**
平板或手机（浏览器支持 WebRTC，用于拍照）、运行 Python 3.10+ 的电脑、ESP32 开发板（NodeMCU-32S，作 BLE 中转）、支持 BLE 心率服务 0x180D 的心率手环、支持 BLE 控制的反馈设备。

**快速开始**

1. 复制 `.env.example` 为 `.env`，填写 `DEEPSEEK_API_KEY`，并按 README 设置模型名、`SERIAL_PORT`、`SERIAL_BAUD`、`INTERVAL_SECONDS` 等；密钥只存本地
2. `pip install -r requirements.txt`
3. `python server.py --port 8080`
4. 本机访问 `http://127.0.0.1:8080/?key=<你的访问口令>`（口令自行设置，勿用示例值，勿公开）
5. 平板访问需 HTTPS，隧道自备；其地址与账号属个人凭据，不在论坛公开
6. 固件在 `esp32_firmware/`，用 Arduino IDE 或 arduino-cli 以 esp32 core 3.x 编译烧录

**已完成（均已实测）**
手动指令下发 → 后端日志与 data_log 记录；模拟画面流 10 帧 → AI 稳定产出剧情与 SET/STOP 指令；`/tts` 返回 200 / audio/mpeg（出声待确认）；服务端 data_log 保留最近 200 个数据点（前端每 2 秒拉取全量重绘）；公网 HTTPS 隧道 → Flask → AI 全链路；图片超 10 秒未更新则暂停 AI 调用；管理后台阈值运行时生效（重启回默认）；固件在 esp32 core 3.3.11 编译通过。

**待完成（尚未实测，请勿当作已可用）**

- ESP32 **尚未烧录**（本机 USB 未枚举，拟改走 USB-TTL）
- **未接入真实心率手环**，熔断/限幅仅有代码逻辑确认
- **未接入真实反馈设备**，「电脑 → 串口 → ESP32 → 体感设备 A」完整闭环尚未跑通
- **波形参数目前未编码进体感设备 A 的报文**（固件内为 TODO，报文只含强度）
- **体感设备 B 的 profile 仅有占位骨架**：UUID 为占位宏、编码函数返回 0（不发送字节），需实物逆向后填入
- 随机事件弹窗端到端未在真实长时间运行中命中（AI 触发为概率行为）
- 其他能力一律「待确认」，以 README 与代码为准

**已知限制与免责声明**
本项目仅供个人技术学习与交流，请遵守当地法律法规，风险自负。心率熔断与限幅属于代码层保护策略，不构成医疗或安全保证；请勿在身体不适或无人看护时使用。默认阈值：心率 >130 强制 STOP、110~130 限幅 50%（可在 Web 后台运行时调整，当前未持久化）。体感设备 A 物理强度上限在固件侧限制为 60。

### 3.2 发帖纪律

1. **一楼一次更新**：版本演进写进合订正文，不再「一层楼一个版本」地追加；连续更新靠编辑，不靠顶帖。
2. **不重复、不引流**：同一链接全文只出现一次（只在合订正文「项目地址」小节）；同一份功能列表只维护一份；不写求 star/求关注/求扩散之类号召式内容。
3. **无签名**：正文与回复末尾都不留署名、落款或「——某某」「某某著」；作者身份由论坛账号档案显示。
4. **措辞中性**：统一使用「体感设备 A / 体感设备 B / 反馈设备」，不出现直白成人向词汇，不贴设备实物图或具体行为描述（与 CONTRIBUTING §3 一致）。
5. **诚实标注**：已实测与待联调分栏写明；未实现的功能（如波形未编码进报文、体感设备 B 仅占位骨架、ESP32 未烧录、未接真实手环/真实设备）不得写成已完成；未确认的能力写「待确认」。
